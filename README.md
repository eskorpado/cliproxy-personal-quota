# Мои квоты · CLIProxyAPI для OpenCode Desktop

Индикатор над полем ввода показывает, сколько личной квоты осталось для выбранной модели. Команда **`/quotas`** открывает панель со всеми доступными квотами и временем следующего сброса. Это оценка расхода: плагин не блокирует запросы и не меняет лимиты на сервере.

## Установка через агента

Если вы уже пользуетесь CLIProxyAPI в OpenCode Desktop, **отправьте агенту один промпт**:

> Установи «Мои квоты» для моего CLIProxyAPI по инструкции https://github.com/eskorpado/cliproxy-personal-quota/blob/main/INSTALL.md

Затем откройте `/quotas` в сессии на встроенном сервере Desktop. Агент возьмёт адрес из существующего подключения; вводить API-ключ, клонировать репозиторий и собирать плагин не нужно. Если подключений несколько и выбор неочевиден, агент спросит только имя провайдера.

**Совместимость:** нужен OpenCode Desktop с поддержкой серверных и GUI-плагинов, RPC и индикаторов над полем ввода (`ComposerPill`). На стороне прокси — HTTPS-провайдер `@opencode/ai/providers/openai-compatible`, `cpa-key-billing` и каталог `/.well-known/cpa-quota-policy.json`. Пустая панель при успешном чтении означает, что для ключа нет подходящих квот; администратор может проверить доступ и метки `quota=N` или `quota.<pool-id>=N`.

## Как считаются квоты

Каталог сервера задаёт семейства моделей, способ учёта, ёмкость и длительность окон. Из ёмкости окна и доли ключа плагин получает личный бюджет; расход берёт из CPA. Окно с известным якорем показывает следующий сброс в местном времени. Для скользящего окна единой даты сброса нет. При временном сбое сверки панель сохраняет подтверждённое значение для того же окна. Если подтверждённого значения нет, панель сообщает о неполной истории.

Сбои сверки записываются в `~/.local/state/opencode/cliproxy-personal-quota/reconciliation.log` (или под `$XDG_STATE_HOME`). Лог содержит время, код проверки, длительность окна и действие плагина.

В расход входят только подтверждённые сопоставимые начисления. Если журнал удалось сверить с аккаунтом, но часть запросов нельзя оценить, панель показывает верхнюю границу остатка («Не более …%») и число неучтённых запросов. Если ни одного начисления подтвердить не удалось или журнал не сходится со сводкой, процента нет.

Ключ использует только серверная часть: она сверяет HTTPS-адрес провайдера с настроенным `origin`, читает публичный каталог без авторизации и отправляет ключ только в API биллинга на том же адресе. Переходы по редиректам отключены. В GUI через локальный RPC передаются результаты для отображения, а не ключ, метка пользователя или журнал событий.

Для ознакомления без подключения к CPA укажите в `options` только `{"mode":"demo"}`. [Пример каталога](quota-policy.example.json) содержит иллюстративные бюджеты, а не готовые тарифы для реального сервера.

## Разработка

Исходники — в `src/`, тесты — в `test/`, команды проверки и сборки — в [`package.json`](package.json). Для локальной разработки нужны Node.js 24 и npm: установите зависимости (`npm ci`), выполните `npm run bundle` и укажите путь к проекту вместо GitHub-пакета в глобальных настройках OpenCode. Версии инструментов для воспроизводимой сборки зафиксированы в lock-файле; GitHub CI сверяет сборку с опубликованным `dist/`. При установке из тега сборка не требуется. [Лицензия MIT](LICENSE).
