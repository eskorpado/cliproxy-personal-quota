# Мои квоты · CLIProxyAPI для OpenCode Desktop

Индикатор над полем ввода показывает, сколько личной квоты осталось для выбранной модели. Команда **`/quotas`** открывает панель со всеми доступными квотами и временем следующего сброса. Это оценка расхода: плагин не блокирует запросы и не меняет лимиты на сервере.

## Установка через агента

Если вы уже пользуетесь CLIProxyAPI в OpenCode Desktop, **отправьте агенту один промпт**:

> Установи и настрой «Мои квоты» для моего подключённого CLIProxyAPI по инструкции https://github.com/eskorpado/cliproxy-personal-quota/blob/v0.1.0/INSTALL.md

Затем откройте `/quotas` в сессии на встроенном сервере Desktop. Агент возьмёт адрес из существующего подключения; вводить API-ключ, клонировать репозиторий и собирать плагин не нужно. Если подключений несколько и выбор неочевиден, агент спросит только имя провайдера.

**Совместимость:** OpenCode Desktop 2.3.2, HTTPS-провайдер `@opencode/ai/providers/openai-compatible`, CLIProxyAPI с `cpa-key-billing` и каталогом `/.well-known/cpa-quota-policy.json`. Пустая панель при успешном чтении означает, что для ключа нет подходящих квот; администратор может проверить доступ и метки `quota=N` или `quota.<pool-id>=N`.

## Как считаются квоты

Каталог сервера задаёт семейства моделей, способ учёта, ёмкость и длительность окон. Из ёмкости окна и доли ключа плагин получает личный бюджет; расход берёт из CPA. Окно с известным якорем показывает следующий сброс в местном времени. Для скользящего окна единой даты сброса нет. Если история неполна или данные устарели, панель прямо это отмечает.

Ключ использует только серверная часть: она сверяет HTTPS-адрес провайдера с настроенным `origin`, читает публичный каталог без авторизации и отправляет ключ только в API биллинга на том же адресе. Переходы по редиректам отключены. В GUI через локальный RPC передаются результаты для отображения, а не ключ, метка пользователя или журнал событий.

Для ознакомления без подключения к CPA укажите в `options` только `{"mode":"demo"}`. [Пример каталога](quota-policy.example.json) содержит иллюстративные бюджеты, а не готовые тарифы для реального сервера.

## Разработка

Node.js 24 и npm. `npm ci`, затем `npm run check`, `npm test` и `npm run build`. Для разработки GUI есть `npm run watch`. В Git включены готовые точки входа из `dist/`, чтобы установка из тега не запускала сборку на машине пользователя. `npm pack` создаёт архив релиза. См. [лицензию MIT](LICENSE).
